AI Prompt LibraryBuild, create, fix and improve any app, tool or design

1. Pickwhat is going wrong
2. Describein your own words
3. Copy and pasteinto Claude with your project open

1What is going wrong?

Pick the closest one. Not sure? Choose the last one.

2Tell it what you see

Write it like you would tell a friend. No tech words needed.

Helpful to mention: what you did, what you expected, what happened instead, and when it started.

If you see an error message, paste it here (optional).

3Copy this and paste it into Claude


        

          
Next: open Claude (Claude Code or the desktop app) with your project, paste, and press Enter. If it asks questions, just answer in plain words.

        
You do not need to know your tech stack. The prompt tells the AI to look at your project and work that out itself.

8 rules for fixing and improving

      
    
        
  1. Root cause before fix. Ask for the diagnosis first, then the patch.
    2. 
        
  2. Give a way to verify. A failing test, a command, a metric. Without it the AI guesses.
    3. 
        
  3. Expected vs actual. Describe the gap, not just the symptom.
    4. 
        
  4. Name the files and paste the evidence. Full error, logs, repro steps.
    5. 
        
  5. Explore, plan, implement, verify. Do not let it write code while it is still reading.
    6. 
        
  6. Set boundaries. State what must not change (APIs, data formats, behavior).
    7. 
        
  7. Measure before optimizing. No speed fix without a baseline number.
    8. 
        
  8. One change at a time. Small diffs you can review and revert.
    9. 
      

    


    
    

      
8 rules for building and creating

      
    
        
  1. Interview before building. Let the AI ask you questions and write a short spec first.
    2. 
        
  2. Keep the spec short and testable. Every requirement is something you can check.
    3. 
        
  3. Build the smallest working slice first. Something real you can click, then widen it.
    4. 
        
  4. One feature or change per prompt. Problems stay traceable.
    5. 
        
  5. Run it after every step. Ask for proof: the command, the result, a screenshot.
    6. 
        
  6. Keep standing rules in a project file. Commands, style and rules live in CLAUDE.md, not in chat.
    7. 
        
  7. Give real style direction. Name what to avoid so the result does not look generic.
    8. 
        
  8. Fresh session to build. Plan in one chat, then build from the saved spec in a clean one.
    9.
